# 方案规划 — `PageView` 日志数据生命周期与归档清理策略 (P2 增强版)

## 一、需求与背景

在执行 `PageView` 历史日志（如保留近 90 天明细）清理策略时，需要确保以下核心业务数据**永久持久化、永不断崖丢失**：
1. **全站总浏览量（`totalViews`）**。
2. **首页与核心一级/二级模块页面的累积浏览量**：
   - `/`（首页）
   - `/blog`（博客列表页）
   - `/links`（友链页）
   - `/portfolio`（作品集页）
   - `/trending`（趋势榜单页）
   - `/books`（读书页）
   - `/tools`（工具箱页）
   - `/about`（关于页）
3. *(文章详情页浏览量已在 `Post.views` 中完成独立持久化与历史回填)*。

## 二、增强方案 A（结构化归档基线 + 90天滚动安全清理）

### 1. 归档数据存储设计 (`SiteConfig.archived_page_views`)
在 `SiteConfig` 表中存储结构化 JSON 归档数据：
```json
{
  "total": 125000,
  "lastCleanedAt": "2026-08-28T08:00:00.000Z",
  "paths": {
    "/": 45000,
    "/blog": 23000,
    "/links": 8500,
    "/portfolio": 12000,
    "/trending": 9800,
    "/books": 6400,
    "/tools": 11300,
    "/about": 9000
  }
}
```

### 2. 核心页面路径归一化规则（Normalize Path）
打点路径包含国际化前缀（如 `/zh/blog`、`/en/blog`、`/blog`）或查询参数，统一按标准路由归一化映射：
- `/`、`/zh`、`/en` $\rightarrow$ `/`
- `/(zh|en)?/blog` $\rightarrow$ `/blog`
- `/(zh|en)?/links` $\rightarrow$ `/links`
- `/(zh|en)?/portfolio` $\rightarrow$ `/portfolio`
- `/(zh|en)?/trending` $\rightarrow$ `/trending`
- `/(zh|en)?/books` $\rightarrow$ `/books`
- `/(zh|en)?/tools` $\rightarrow$ `/tools`
- `/(zh|en)?/about` $\rightarrow$ `/about`

## 三、详细实现步骤

### 1. 后端改造 (`packages/api/src/routers/analytics.ts`)

#### A. 新增安全清理 Procedure (`analytics.cleanup`)
- **权限**：`adminProcedure`
- **参数**：`daysToKeep: z.number().int().min(30).max(365).default(90)`
- **执行逻辑**：
  1. 计算截止时间 `cutoff = now - daysToKeep`。
  2. 获取现有的 `SiteConfig[archived_page_views]` 配置（若无则初始化为 0 与空映射）。
  3. 统计并计算 `cutoff` 之前即将被清理的数据：
     - **全站清理行数**：`expiredTotal = count({ where: { createdAt: { lt: cutoff } } })`
     - **关键页面清理行数**：通过 Prisma `$queryRaw` 按归一化 path 聚合统计即将被删除的行数。
  4. 将统计结果原子累加并更新至 `SiteConfig[archived_page_views]`。
  5. 执行物理删除：`deleteMany({ where: { createdAt: { lt: cutoff } } })`。
  6. 返回清理摘要 `{ success: true, deletedCount: expiredTotal, retainedDays: daysToKeep, archivedSummary }`。

#### B. 升级概览查询 (`analytics.summary`)
- 返回全站历史累计 `totalViews`（当前明细行数 + 归档总数）。
- 返回核心页面的历史累计数据 `keyPageViews`（当前明细行聚合 + 归档各路径基数）。
- 保持近 7/30/90 天的活跃趋势图与热门排行的毫秒级高性能查询。

### 2. 自动化维护脚本 (`packages/db/scripts/prune-analytics.ts`)
提供独立跨平台 CLI 脚本：
```bash
# 在 root package.json 中提供
pnpm db:prune-analytics --days=90
```
- 支持配置保留天数（默认 90 天）。
- 可挂载至 Linux 服务器系统 Cron、Docker 容器定时器或 GitHub Actions Workflow 自动化执行。

### 3. 后端单元测试覆盖 (`tests/analytics-cleanup.test.ts`)
- 验证清理前后的 `totalViews` 和核心页面累计访问量一致性。
- 验证路径归一化逻辑（多语言前缀合并）。
- 验证清理幂等性与边界条件（空表清理、重复清理）。
